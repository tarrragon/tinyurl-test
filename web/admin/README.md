# web/admin（後台）

看點擊數據與系統 log 的地方，需要登入，行銷與工程師看到的頁面不同。

## 功能

行銷（`marketing`、`marketing_lead`）：

- 活動成效：每條連結、每個活動的點擊數，依時間、管道（簡訊 / Email / 廣告）拆分。
- 管道比較：同一個活動在不同管道的點擊數。
- 客群比較與轉換：一次發送裡各客群的點擊、不重複點擊、轉換與轉換金額；活動的每次發送分開列出。
- 匯出報表（`marketing_lead` 以上）：活動報表，以及一次發送裡每位收件人有沒有點擊、有沒有購買（交回 CRM 做下一次分群）。

工程師（`engineer`）：

- 連到 Grafana 的入口。請求 log（逐筆的時間、短碼、回應狀態、延遲、來源 IP、User-Agent、處理的後端）、錯誤與限流、Go 與 Laravel 的對照都在 Grafana 上看，後台不另外顯示，理由見 [API 與路由規格](../../docs/api.md)〈請求 log〉。

管理者（`admin`）：

- 使用者與角色管理。
- 伺服器金鑰的建立與撤銷（電商回報轉換用）。

完整對照見 [docs/auth-and-roles.md](../../docs/auth-and-roles.md)。

## 延後的功能

**依裝置與地區拆分**目前不做。之後要做時可以回溯，因為 `click_events` 保留了每筆點擊的原始 User-Agent 與 IP：從它們推算裝置類型與國家，補進彙總表即可。

- **觸發條件**：行銷提出要依裝置或地區比較活動成效。
- **回溯的範圍有限**：只回溯得到還在保留期內的 `click_events` 分割區，被刪掉的月份補不回來。保留期限目前還沒定（見 [開發順序](../../docs/roadmap.md)〈練習環境跳過的項目〉的個人資料保留期限），定的時候要把這個需求一起考慮。

## Docker
